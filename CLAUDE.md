# Botalka — инструкции для Claude Code

## О проекте

Платформа подготовки к ЕГЭ: квизы, дуэли между игроками в реальном времени, рейтинг.
Первый предмет — профильная математика (часть 1), дальше русский. В перспективе —
ИИ-проверка сочинений и распознавание фото второй части.

**Название** — от «ботать», это официальное имя продукта, не рабочее.

**Позиционирование: спортзал, а не школа.** Школково и «Стобалльный репетитор» продают
курсы и уроки. Мы продаём регулярную короткую тренировку: зашёл на 15 минут, позанимался,
ушёл. Отсюда всё остальное — короткие квизы вместо занятий, стрики, дуэли, план на день
с оценкой в минутах. Видеоразборы задач в будущем — тоже в этой логике: короткие разборы
конкретной задачи, а не лекции.

**Целевой экзамен — ЕГЭ 2027** (ЕГЭ 2026 уже прошёл). Платформа рассчитана на любой год:
год спецификации хранится в данных (`task_types.year_spec`), не в коде.

- **Планы:** `docs/ROADMAP.md` — что делаем и в каком порядке. Сверяться перед новой задачей
- **Архитектура и схема БД:** `docs/ARCHITECTURE.md`
- **Формат задач:** `docs/CONTENT.md`
- **Деньги:** `docs/MONETIZATION.md`
- **Дизайн:** `docs/DESIGN.md` — токены и правила. Макеты: `docs/reference/screens-v1.html`
  (в референсе продукт называется «Балл» — у нас везде «Боталка»)

## Стек

Backend — Python 3.12 + FastAPI + Postgres + Redis. Frontend — Next.js 16 (App Router) +
TypeScript + Tailwind. Бот — aiogram 3. Всё в docker compose, деплой на один VPS.

## Правила, которые легко нарушить

1. **Правильный ответ никогда не уходит на клиент** до завершения попытки. Проверка
   ответа — только на сервере. Иначе рейтинг и дуэли бессмысленны
2. **Никакой предметной специфики в коде.** Никаких `if subject == "math"`. Различия
   живут в данных (`task_types`, `answer_type`)
3. **Каждая попытка пишется в `attempts`** — это основа статистики, повторений и
   персонального плана. Не оптимизировать «лишние» записи
4. **Состояние дуэли — в Redis**, не в памяти процесса
5. **Таймеры авторитетны на сервере.** Клиентский таймер — только для отрисовки
6. **Нормализация ответов**: запятая→точка, обрезка пробелов, регистр. Ложная ошибка
   из-за формата — самый быстрый способ потерять пользователя
7. **Стоимость ИИ-вызовов пишем в БД** при каждой проверке
8. Секреты (токен бота, ключи API, DSN) — только в `.env`, никогда в клиентском коде и
   никогда в git

## Нумерация заданий ЕГЭ

Структура КИМ меняется по годам — номера заданий хранятся в `task_types` с привязкой к
году спецификации. **Не полагаться на память при заполнении типов заданий:** сверять с
актуальной спецификацией ФИПИ.
