# Боталка — тренажёр для подготовки к ЕГЭ

Подготовка к ЕГЭ устроена как спортзал, а не как школа: не курсы и уроки, а короткая
регулярная тренировка. Зашёл на пятнадцать минут, решил квиз, разобрал ошибки, ушёл.
Отсюда всё остальное — серии дней, дуэли, задача дня, план на сегодня с оценкой в минутах.

Первый предмет — **профильная математика, часть 1**. Дальше русский язык.
Целевой экзамен — ЕГЭ 2027; год спецификации хранится в данных, а не в коде, поэтому
платформа переживает смену структуры КИМ.

## Что уже работает

- **Квизы** — десять задач, навигатор между вопросами, пропуск, подсказки, разбор каждой
  ошибки сразу после ответа
- **Дуэли по ссылке** — оба решают один набор задач в удобное время; работает при нулевом
  онлайне, поэтому годится как инструмент сарафана
- **Онлайн-матч** на WebSocket с подбором соперника, живым таймером и реконнектом
- **Задача дня** — одна на всех, таблица по времени решения
- **Пробники** — полный вариант на время, проверка в конце, как на экзамене
- **Статистика** по номерам заданий, слабые темы, работа над ошибками
- **Турниры, кланы, магазин косметики** за монеты — косметика ни на что не влияет
- **Банк из 264 задач** по всем двенадцати номерам части 1, 260 из них с разбором

## Банк задач

Задачи взяты из [открытого банка ФИПИ](https://ege.fipi.ru/bank/). Права на условия и
чертежи принадлежат ФИПИ; здесь они используются для подготовки к экзамену, источник
указан у каждой задачи и виден ученику под условием.

Открытый банк не публикует ответы, поэтому ответы считаются и проверяются своими силами:

```
tools/fipi_fetch.py     выгрузка условий и картинок
tools/fipi_parse.py     разбор MathML и HTML в YAML-черновики
tools/fipi_classify.py  раскладка по номерам заданий КИМ
tools/fipi_solve.py     решение с двойной проверкой
tools/fipi_geometry.py  шаблоны школьных свойств для планиметрии и стереометрии
tools/fipi_manual.py    ответы, посчитанные вручную
tools/fipi_rank.py      ранжирование сложности
tools/fipi_audit.py     независимая проверка готового банка
```

Главное правило конвейера: **ответ принимается, только если получен двумя независимыми
способами и они совпали.** Символьное решение проверяется подстановкой в исходное условие,
комбинаторика — полным перебором исходов, экстремумы — сканированием по сетке. Если
способы разошлись или второй неприменим, задача остаётся черновиком и до учеников не
доходит: неверный ключ ученик воспринимает как «тренажёр врёт», и это не чинится
извинениями.

`fipi_audit.py` затем пытается опровергнуть уже готовые ответы — другой дорогой, чем та,
которой они получены, — и отдельно сообщает, сколько задач перерешано независимо, а
сколько проверено только на здравый смысл.

## Запуск

```bash
cp .env.example .env     # заполнить токен бота и JWT_SECRET
make up                  # docker compose: postgres, redis, backend, web
make migrate             # миграции
docker compose exec backend python -m app.cli.import_content   # залить банк задач
```

Сайт — http://localhost:3000, API — http://localhost:8000/docs.

Виджет Telegram не работает с localhost, поэтому для локальной отладки есть вход без
Telegram: `DEV_LOGIN=true` в `.env`. **В продакшене обязательно `false`** — иначе войти
сможет кто угодно.

Подробнее: [docs/DEV.md](docs/DEV.md).

## Стек

Backend — Python 3.12, FastAPI, Postgres, Redis. Frontend — Next.js 16 (App Router),
TypeScript, Tailwind. Бот — aiogram 3. Всё в docker compose, деплой на один VPS.

## Структура репозитория

```
backend/   FastAPI: API, WebSocket-дуэли, проверка ответов
web/       Next.js: сайт и, позже, Telegram Mini App (одна кодовая база)
bot/       Telegram-бот (aiogram): вход в Mini App, напоминания, уведомления о вызовах
content/   банк задач в YAML + картинки к ним
tools/     конвейер банка: выгрузка, разбор, решение, проверка
docs/      планы и решения
```
