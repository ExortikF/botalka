# План разработки

## Принципы

1. **Один предмет, один режим, до конца.** Профильная математика, часть 1 (задания с
   коротким ответом). Русский и вторая часть — только после того, как первый предмет
   работает и им пользуются.
2. **Контент важнее кода.** Платформа без 500+ выверенных задач не нужна никому.
   Сбор и разметка задач идёт параллельно с разработкой, а не после.
3. **Играбельность в одиночку.** Дуэли требуют второго игрока онлайн. Пока пользователей
   мало — соревнование должно работать асинхронно (см. Спринт 4).
4. **Ничего не выкатываем без метрик.** С первого дня: регистрация → первый квиз →
   возврат на второй день. Без этого непонятно, что чинить.

## MVP (~6–8 недель при работе вечерами)

Цель MVP: школьник заходит, решает квиз из 10 задач, видит разбор ошибок, вызывает друга
на дуэль и попадает в рейтинг. Возвращается на следующий день, потому что есть серия дней.

### Спринт 0 — фундамент (3–5 дней)

- [ ] Репозиторий, docker-compose: Postgres + Redis + backend + web
- [ ] FastAPI-скелет, health-check, миграции (Alembic)
- [ ] Next.js-скелет, темы, базовые компоненты
- [ ] Аутентификация: вход через Telegram (не через email/пароль — школьники и так все в ТГ)
- [ ] Деплой на VPS: nginx + HTTPS, CI на GitHub Actions (тесты + деплой по пушу в main)

**Готово, когда:** на боевом домене открывается пустая страница и работает вход через ТГ.

### Спринт 1 — банк задач (5–7 дней, параллельно с остальным)

- [ ] Формат задачи (YAML), схема в БД, импортёр `content/ → БД`
- [ ] Проверка ответа: число, число с допуском, строка, последовательность цифр
- [ ] Рендер формул (KaTeX) и картинок к задачам
- [ ] **50 задач вручную** по 5 типам заданий части 1 — чтобы пощупать формат
- [ ] Админка на минималках: просмотр задач, правка, пометка «битая»

**Готово, когда:** задачу можно добавить файлом, она рендерится и корректно проверяется.
Подробности формата — [CONTENT.md](CONTENT.md).

### Спринт 2 — одиночный тренажёр (5–7 дней)

- [ ] Экран квиза: 10 задач, таймер, ввод ответа, мгновенная проверка
- [ ] Экран результата: что верно, что нет, разбор к каждой ошибке
- [ ] Режимы: «по типу задания» (тренирую номер 7) и «микс» (случайные 10)
- [ ] История попыток, простая статистика: процент по каждому типу задания
- [ ] Серия дней (streak) + счётчик решённых задач

**Готово, когда:** можно решать каждый день и видеть, какие типы заданий проседают.

### Спринт 3 — дуэли (7–10 дней) ⚠️ самая рискованная часть

- [ ] WebSocket-слой: комната, состояние матча, реконнект
- [ ] Матч: 5 задач, оба игрока получают одни и те же, очки = верно + скорость
- [ ] Подбор соперника: очередь в Redis, бот-заглушка если никого нет за 15 секунд
- [ ] Вызов друга по ссылке (важнее случайного подбора — сарафан идёт отсюда)
- [ ] Рейтинг Эло, таблица лидеров: за неделю и за всё время
- [ ] Обработка разрывов: ушёл со страницы → техническое поражение через 30 секунд

**Риск:** реалтайм — единственное место, где легко утонуть. Если к концу срока не
работает стабильно — режем до асинхронного формата из Спринта 4 и возвращаемся позже.

### Спринт 4 — асинхронные соревнования (3–4 дня)

Страховка от пустого онлайна и, возможно, вообще более удачный формат.

- [ ] **Задача дня**: одна и та же для всех, рейтинг по времени решения, сбрасывается в полночь
- [ ] **Челлендж**: решил набор — отправил ссылку другу, он решает те же задачи, сравнение результатов
- [ ] Недельная лига: топ-20 по очкам за неделю

### Спринт 5 — запуск (3–5 дней)

- [ ] Телеграм-бот: вход в Mini App, напоминание «серия сгорит», уведомление о вызове
- [ ] Онбординг: первый квиз без регистрации, регистрация после него
- [ ] Аналитика (Метрика/Umami) + воронка: зашёл → начал квиз → закончил → вернулся
- [ ] Страница донатов, политика ПДн (152-ФЗ), правила
- [ ] Довести банк до **300–500 задач**, покрыв все типы части 1
- [ ] Мягкий запуск: 2–3 профильных ТГ-канала/чата, посмотреть на удержание

**MVP считается успешным, если:** из 100 пришедших 30 доходят до конца первого квиза и
10 возвращаются на второй день. Если возврат ниже — проблема в контенте или в игре, и
следующий предмет добавлять рано.

## Порядок работ, утверждённый 12.08.2026

Спринты 0–2 сделаны. Дальше идём так:

1. **Дизайн по референсу** — токены, боковое меню, лендинг, главная, квиз ← сейчас
2. **Личный кабинет** — профиль, статистика, активность, достижения
3. **Допилить квизы** — навигатор, пропуск, пометка «решено с подсказкой», типы режимов
4. **Удобный банк задач** — как наполнять и редактировать, продумываем вместе.
   До этого момента в банке лежит несколько тестовых задач, и это нормально
5. **Дуэли** — механика из макетов: 7 раундов, вопрос обоим одновременно, очко за
   верный и быстрый ответ, тайбрейк по суммарному времени, рейтинг только по дуэлям

Домен и хостинг — после того, как будет что показывать.

## Структура интерфейса (уточнено 12.08.2026)

- **Главная** `/app` — план на день и точки входа. Справа сверху иконка профиля,
  по ней переход в профиль со статистикой
- **Профиль** `/app/profile` — только про пользователя: дашборд, достижения
  (оформленные как в играх), рейтинг, статистика. Никаких задач и квизов
- **Квизы** `/app/quiz` — выбор предмета плиткой, затем выбор номера задания
  либо сборка своего квиза из нескольких номеров
- **Геометрия** — позже: картинки к задачам и возможность рисовать поверх них
  прямо в браузере (черновик к задаче)

## После MVP

### Этап 1. Русский язык, тестовая часть (2–3 недели)

Проверка тем же движком — там те же типы ответов (слово, цифры, последовательность).
Основная работа — контент и типы заданий, кода почти нет. Хорошая проверка того, что
платформа действительно предметно-независимая.

### Этап 2. Удержание и социальность (3–4 недели)

То, что реально влияет на возвраты, — важнее нового предмета:

- Персональный план: система видит слабые типы заданий и сама собирает квиз
- Интервальные повторения: ошибочная задача возвращается через 1/3/7/21 день
- Классы и учителя: учитель заводит группу, видит статистику класса, выдаёт задания
- Друзья, командные дуэли 3×3, сезонные турниры
- Достижения и косметика (аватары, рамки) — то, что потом можно продавать

### Этап 3. ИИ-проверка сочинений (4–6 недель) — главная монетизируемая фича

Начинать с **русского языка, сочинение (задание 27)**, потому что критерии формализованы
и есть с чем сверяться.

1. Оцифровать официальные критерии в структурированный вид: каждый критерий — отдельная
   проверка со своей шкалой, а не «оцени сочинение целиком»
2. Пайплайн: одна LLM-проверка на критерий → агрегация → балл + объяснение по каждому
   пункту + подчёркнутые места в тексте
3. **Калибровка:** собрать 50–100 сочинений с настоящими экспертными баллами и мерить
   расхождение. Без этого мы просто продаём мнение модели
4. Честная формулировка в интерфейсе: «предварительная оценка, не гарантирует балл на
   экзамене» — иначе первый же расхождённый балл убьёт доверие
5. Экономика: одна проверка — считанные центы по API, продаём пакетами (см. MONETIZATION.md)

Позже — сочинение по литературе и английскому (там критерии мягче, риск ошибки выше).

### Этап 4. Фото второй части (4–6 недель) — технически самое сложное

Распознать рукописное решение по фото и проверить ход рассуждений.

- Мультимодальная модель по фото → LaTeX/текст решения → проверка по критериям задания
- **Каждая задача второй части должна иметь свои критерии в банке** — иначе проверять не
  с чем. Это контентная работа, и её объём больше, чем кажется
- Начать с самых формализованных: уравнение (13) и неравенство (15) — там ход решения
  предсказуем. Геометрия и параметр — в последнюю очередь
- Обязательный человеческий контур: пользователь может оспорить оценку, спорные уходят
  в очередь на ручной разбор. Заодно это данные для улучшения промптов

### Этап 5. Остальные предметы

Информатика (можно давать реальное выполнение кода — сильная фича), физика, обществознание,
биология. Порядок — по спросу и по тому, насколько дёшево достать качественный контент.

## Что осознанно не делаем в MVP

- Видеоуроки и теория — мы тренажёр, а не онлайн-школа
- Мобильные приложения — веб + Telegram Mini App закрывают всё
- Оплата — до MVP только донаты, платёжку подключаем к ИИ-проверкам
- Своя модель — только API, пока не появится объём, оправдывающий дообучение
- Подготовка к ОГЭ — тот же движок, но другая аудитория и маркетинг, отдельная история

## Главные риски

| Риск | Что делаем |
|---|---|
| Контент не набирается, задач мало | Контент — отдельный поток с первой недели, оценивать в задачах/неделю |
| Пустой онлайн, дуэли не с кем играть | Асинхронные форматы (Спринт 4) + боты-заглушки |
| Авторские права на задачи ФИПИ | Открытый банк ФИПИ + собственные переформулировки; юридически проверить до платных функций |
| Сезонность: с июня по август аудитории нет | Запуск целить в сентябрь–октябрь; лето — на разработку |
| ИИ-проверка ошибается и роняет доверие | Калибровка на реальных экспертных баллах + возможность оспорить |
| Донатов не хватает на API | Бесплатно — ограниченное число проверок, дальше пакеты |
