# Банк задач

Контент — узкое место проекта. Код напишется за недели, а 500 выверенных задач сами не
появятся. Поэтому формат задачи фиксируем раньше, чем пишем интерфейс.

## Формат

Одна задача — один YAML-файл в `content/<subject>/<task_type>/<id>.yaml`.
Файлы, а не сразу база: их видно в git, можно править в редакторе и ревьюить диффом.
Импортёр заливает их в Postgres.

```yaml
id: math_prof_07_0012
subject: math_prof
task_type: 7          # номер задания в КИМ
difficulty: 3         # 1–5, субъективно; уточняется по реальной статистике решений
statement: |
  Найдите корень уравнения $\log_{3}(2x - 5) = 2$.
image: null           # путь относительно content/ либо null
answer:
  type: number        # number | number_tolerance | string | digits | multi
  value: 7
solution: |
  ОДЗ: $2x - 5 > 0$. По определению логарифма $2x - 5 = 9$, откуда $x = 7$.
hints:
  - Вспомните определение логарифма.
source:                 # источник указываем всегда
  kind: exam            # own | exam | demo | fipi | book | other
  year: 2024
  ref: "7"              # номер в источнике
  label: "ЕГЭ 2024, основная волна"   # если пусто — соберём из kind, year и ref
  url: null
status: live            # draft | live | broken
```

### Типы ответов

| type | Проверка | Пример |
|---|---|---|
| `number` | точное совпадение после нормализации (`,`→`.`, пробелы) | `7`, `-0.5` |
| `number_tolerance` | с допуском, поле `tolerance` | `3.14` ± `0.01` |
| `string` | без регистра и пробелов, можно список синонимов | `нейтральный` |
| `digits` | последовательность цифр, порядок важен | `1324` |
| `multi` | набор чисел без учёта порядка | `2;5;7` |

Всё нормализуем на сервере. Самая частая причина ложной ошибки — запятая вместо точки
и лишний пробел; на этом теряется доверие быстрее, чем на чём-либо ещё.

Подпись источника видна ученику под условием мелким шрифтом — это важно: задача
воспринимается как настоящая, а не выдуманная. У собственных задач подписи нет.

## Откуда берём задачи

Разобрано 12.08.2026.

1. **Варианты прошлых лет и демоверсии ФИПИ** — основной источник. Публикуются
   официально и вместе с ответами, что критично: тренажёру нужен эталонный ответ
2. **Генерация по шаблонам** — для типовых номеров (вычисления, проценты, простые
   уравнения) один параметризованный шаблон даёт сотни вариантов. Самый дешёвый способ
   набрать объём
3. **Ручное написание** — для того, что не шаблонизируется
4. **Наработки из `EssayApp/fipi_data`** — посмотреть, что там уже собрано

### Чего не делаем

- **Открытый банк ФИПИ выкачивать целиком не стоит.** В нём 997 заданий по профильной
  математике, но: страница помечена «Все права защищены», задания отдаются картинками
  через AJAX, а **ответов там нет** — импорт даст условия, которые всё равно придётся
  дорешивать вручную. Брать оттуда точечно и перерабатывать формулировку — можно
- **Банк Школково не копируем.** Это коммерческий продукт действующей школы;
  выкачать и опубликовать у себя — прямое нарушение их прав, а не серая зона
- **Решу ЕГЭ** — по опыту много неактуальных задач, структура устарела относительно
  нынешних КИМ

## Генератор задач

`tools/generate_bank.py` — 40 шаблонов на все 12 номеров части 1. Каждый шаблон
подставляет случайные, но «красивые» параметры (ответ получается целым или короткой
десятичной дробью) и сам считает ответ.

```bash
python3 tools/generate_bank.py --per-template 12   # пишет YAML в content/
python3 tools/verify_bank.py                        # независимая перепроверка
docker compose exec backend python -m app.cli.import_content
```

**Почему проверок две.** Генератор проверяет себя вторым способом внутри (подстановка
корня в уравнение, перебор исходов, численная производная). Но если формула в шаблоне
неверна, такая проверка может повторить ту же ошибку. Поэтому `verify_bank.py`
разбирает **текст готового условия** регулярками и решает задачу заново, не заглядывая
в генератор. Расхождение — падение с указанием файла.

Прогон 12.08.2026: 468 задач, все 468 перерешаны независимо, расхождений нет.

## Как добавлять задачи

Два пути, оба ведут в одну таблицу:

- **Админка** `/app/admin` — форма с предпросмотром формул. Права выдаются командой
  `docker compose exec backend python -m app.cli.make_admin <tg_id>`
- **YAML-файлы** в `content/` + `python -m app.cli.import_content` — удобно для
  массовой заливки и код-ревью через git

Обе двери проверяют одно и то же: эталонный ответ обязан проходить собственную
проверку, а публикация без разбора запрещена.

## Требования к качеству

- У каждой live-задачи есть разбор. Задача без разбора — `draft`, в квизы не попадает
- Каждая задача решена вручную хотя бы раз до перевода в `live`
- Кнопка «в задаче ошибка» в интерфейсе; три жалобы → автоматически `broken` и вон из выдачи
- Раз в неделю смотреть задачи с решаемостью <10% и >95% — это либо ошибка в ответе,
  либо неверная сложность

## Целевой объём

| Этап | Задач | Комментарий |
|---|---|---|
| Спринт 1 | 50 | пощупать формат, 5 типов заданий |
| MVP | 300–500 | все типы части 1, минимум 20 на тип |
| Через полгода | 2000+ | хватает, чтобы задачи не повторялись при ежедневном решении |

## Про нумерацию заданий

Структура КИМ меняется по годам. Поэтому номер задания — это поле в `task_types` с
привязкой к году спецификации, а не хардкод в коде. Перед стартом наполнения сверить
типы заданий с **актуальной спецификацией ФИПИ на нужный год** — не по памяти и не по
чужим сайтам.
